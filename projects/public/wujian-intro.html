卷一 · 第一章要解决的问题：文博教学的「三不可」困境

1.1一件国宝的发现，与一门学科的难题

1996年10月，长沙市中心五一广场走马楼西侧的平和堂商厦工地，在编号J22的古井里，工作人员发现了沉睡一千七百余年的简牍。最终清点，出土简牍总数超过十万枚——超过此前全国出土简牍的总和。这批三国孙吴时期的简牍，内容涉及赋税、户籍、仓廪、司法、书信，几乎是一部埋在地下的孙吴基层行政档案全书，被学界誉为「二十世纪中国最重要的考古发现之一」。

然而，从古井中重见天日，只是这批简牍「第二次生命」的开始。饱水、变形、粘连、霉变、字迹漫漶——要让一枚湿软如面条的竹简重新变得可读、可存、可研究，需要经历揭取、清洗、绑夹与核对、饱水保存、脱色、脱水六道工序，历时数年。每一道工序都是高度专业化的文物保护技术，每一个决策背后都有材料学、化学、生物学的依据。

问题就出在这里。这样一门弥足珍贵、且极具教学价值的实践学科，在传统课堂上却几乎「没法教」，其困境可以概括为「三不可」：

不可及

文物本体存于库房，修复现场不对外开放。学生一辈子可能都没有机会亲手触碰一枚饱水竹简——这枚竹简出土时含水率高达471%，手一抖就是一个不可挽回的损失。

不可逆

修复是「一次性」的艺术。揭取时层位信息一旦破坏即永久丢失；脱色时温度失控，墨迹可能就此消失。真实文物上不容许任何试错，而「试错」恰恰是学习最核心的机制。

不可见

修复决策的逻辑——为什么用竹刀不用铁铲、为什么浓度是0.2%而不是0.1%——全部沉淀在专家的头脑与几百页的考古报告里。学生看到的只是「结论」，看不到「得出结论的过程」。

1.2传统教学手段的四个失效

其一，讲授失效。教师对着幻灯片讲「揭取要按叠压关系确定次序」，学生记住的是一句要背的话，而不是「面对a→b→c的叠压记录时如何推理」的能力。知识以结论的形式被灌输，考完即忘。

其二，视频失效。纪录片能展示画面，但学生始终是旁观者。看一百遍修复师傅运笔，不等于自己知道「力度出区间会怎样」——而后者才是修复决策的核心。

其三，题库失效。普通在线题库出不了好题：文物保护的题目需要真实数据、真实约束、真实后果，编造的情景题既不严谨也无说服力；而把考古报告原文丢给学生，又超出本科生的阅读负荷。

其四，评阅失效。即便设计出了好题，开放性作答的评阅需要教师逐份阅读、逐条批注。一个教学班几十人、每人十几道细问，反馈周期动辄一周——而学习科学早已证明，反馈延迟越久，教学效果衰减越严重。

「学生面对的是结论，而非得出结论的过程；是文字，而非承载文字的文物本体。」 —— 本工坊立项时的核心判断

1.3本应用场景给出的解法

走马楼三国吴简修复工坊，是一个以真实考古报告为唯一内容来源、以生成式人工智能为教学引擎的沉浸式虚拟实训场景。它不满足于「把课件搬上网」，而是针对三不可逐一对症：

  • 以「虚拟仿真」破「不可及」——六个环节各建一台仿真工作台，学生在浏览器里就能排叠压次序、调药剂浓度、控制脱水温度，把十万枚简牍的修复现场搬到每个人面前；
  • 以「允许失败」破「不可逆」——在仿真环境里，选错工具简会断在半空、浓度压不住菌第10个月就长白斑，每一次失败都被如实呈现为后果，但清零重来不花一分钱、不损一枚真简；
  • 以「数据反推」破「不可见」——所有细问不预设结论，直接给出考古报告的原始数据（工时统计、测色数值、收缩率实测），学生必须自己走完「证据→推理→判断」的全链路；
  • 以「AI即时评阅」破「评阅失效」——数字人助教「小简」依据教师预置的评阅要点，秒级给出「成立/部分成立/不成立」三档判定与流式解析，让每个学生都拥有一位全天候在线的专属导师。

卷一 · 第二章建设理念：四条设计公理

2.1公理一：让证据说话，让学生动手

本工坊的全部内容出自《长沙走马楼三国吴简的保护与整理》——这是修复工作的一手技术报告，记录了每一道工序的做法、参数、数据与教训。我们把这批材料视为唯一的内容来源，奉行严格的「内容纪律」：

  • 数据只能来自报告，改动任何数字前先确认章节出处；
  • 报告不同章节之间存在口径差异的六处（有字吴简总数、出土总数、大木简数量、坨数、纤维素结晶度、防腐药剂名），逐条登记在大厅「报告内部数字出入备案」中，明确本工坊采用哪一个口径，绝不私自统一；
  • 「新洁尔灭」（第二章筛选实验）与「复方新洁尔灭」（第三章实际使用）不是同一种药，绝不合并——这种「较真」本身就是学科精神的示范。

在证据之上，学生不是读者，而是操作者与决策者。每一道题都不问「报告说了什么」，而问「你面对这些数据，怎么判断、怎么选、怎么做」。

2.2公理二：有数据处，从数据反推结论

这是贯穿十七道细问的设计总纲。试举三例：

例一 · 揭取环节的排序题

给出揭取I区记录到的叠压关系：a→b→c、b→d、d→e，其中c坨自身细分为c①→c②→c③。学生要排出揭取次序——而系统接受任何满足先后约束的合法排列。因为考古证据本来就允许多解，把「与某一示例排列一致」作为唯一标准答案是反科学的。学生还必须单独指出哪些单位对的次序「不可判定」，这是本题的核心失分点。

例二 · 清洗环节的工时反推题

给出真实已知条件：竹简共73631枚、每枚清洗耗时40～50分钟、分6道工序、每天工作10小时（按每月22个工作日计）。学生要反推总工期、并计算「人力减半后工期变为几年」——这不是算术题，是从真实数据理解工程决策：为什么修复工程要以「年」为单位规划。

例三 · 脱色环节的反常数据解释题

给出AAS法实测铁含量：处理液中的铁随浓度升高单调递增（符合预期），但竹简中的铁在低浓度（0.1%、0.25%）时反而高于未处理的对照组，到0.5%以后才开始下降。学生要解释这条「反常曲线」——好的教学不是给规律，而是给反常，逼学生动用化学知识重构机理。

2.3公理三：仿真管「手」，细问管「脑」

每个环节页面分三节：「为什么必须有这个环节」（读）→「上机操作」（动手）→「细问」（动脑）。仿真工作台与细问之间有严格的分工纪律：

  • 仿真工步只做操作——排次序、挑工具、调参数、逐段推进；反馈只说三件事：发生了什么现象、指标掉了多少、规程怎么规定；
  • 仿真反馈不讲机理、不讲为什么——机理、推理、计算、设计全部留给紧跟其后的细问去追问。判据很硬：一条反馈若把某道细问的评阅要点说出来了，就是越界，必须改成只述现象；一个工步若本身就是某道细问的题干，就换成另一个手上的动作；
  • 仿真不判分、不进评阅链路——这一节不计入进度，产出是一份操作记录，学生可以「把这次操作记录带给小简」，导师会针对代价最大的那一步追问，但仍然坚持先答后评、不代他复盘。
为什么这样分？如果仿真把机理讲了，细问就变成复述；如果细问先于操作，学生就没有动手的体感。先动手、再被追问——顺序本身就是教学法。

2.4公理四：先答后评，不代答

数字人导师「小简」的行为被写死在系统提示词总纲里，几条硬约束：

  • 先答后评：学习者没给答案之前，不给答案、不给要点；
  • 一次只推进一小问，不把(a)(b)(c)一次性抛出；
  • 计算题必须要过程，只给数字的退回重做，口径（取中值、按几个工作日）要写明；
  • 排序题必须问「哪些不可判定」——排出唯一序列而不指出不可判定的单位对，是本类题的核心失分点；
  • 评阅给「成立/部分成立/不成立」+依据+缺口，不打分数；
  • 只用注入的报告数据回答，不编造数字与出处；报告本身口径有出入的地方主动说明。

这四条公理共同指向一个目标：把「教师在场的一对一教学」变成可规模化的软件形态，同时保住教育学最珍贵的东西——学生自己走完思考全程的权利。

卷一 · 第四章六大环节详解：从井底到书页的完整修复链

六道工序覆盖了从「井里取出来」到「能被人读」的全过程。下面逐一展开每个环节的定位、关键数据、工作台操作与细问设计。

一揭取唯一一道不可重来的工序

环节定位。J22古井内的简牍并非散乱堆放，而是成坨叠压、卷成筒状。揭取的本质是考古发掘：每揭一坨都要记录它与周围简坨的叠压关系——这些关系是日后恢复简册原始顺序的唯一依据，揭坏了就永久丢失。所以这一环节的口号是「唯一一道不可重来的工序」。

关键数据。揭剥立面图揭示的规律：每枚简端平的一面是有字正面、弧形面是背面；上半部分有字面朝下，下半部分正好相反——工作人员据此按编绳磨痕复制新竹片、编联成册、逐枚标号、模拟卷起，通过观察横断面反推原始卷圈顺序。I区记录到的叠压关系如 a→b→c、b→d、d→e，c坨自身细分 c①→c②→c③。

工作台操作。排五个小坨的揭取次序 → 清理横断面找缝 → 选竹刀尖（而非金属工具）→ 点蘸润滑 → 定2～3厘米步距逐段剥离 → 托举。做错会看到：次序违反已记录的叠压关系，层位信息当场作废；捏住一端直接提起来，简断在半空。

细问设计（3道）。

排序题判断题机理分析题
  • q1 排序题：给定叠压记录排揭取次序，合法解不唯一，必须指出哪些不可判定；
  • q2 判断题拆五小问：五条关于揭取的陈述逐条判正误，判「错」要写正确表述、判「对」要说明它对后续工序意味着什么——逐条作答、逐条评阅、逐条提交；
  • q3 机理分析题：从「有字面朝向的上下反转」这一规律出发，解释工作人员如何用模拟编联反推卷圈顺序。
二清洗让字迹第一次真正可见

环节定位。出土简牍包裹着泥污，字迹完全不可见。清洗是第一次让文字「重见天日」——但也是最危险的工序之一：竹黄面上仅存的墨迹，可能被一次力度失误抹掉。

关键数据。竹简共73631枚，每枚清洗耗时40～50分钟，分6道工序（取简→开卡入槽→清理污物→清理字面→脱色前清洗→再清洗），每天工作10小时、每月22个工作日。竹黄面「吸墨渗透好但耐磨强度低」，竹青面「组织致密不易书写但字迹耐磨持久」——两组看似相反的性质源于同一个材料学原因。清洗工具经历三代演变：第一代（粗排笔、毛刷）→ 第二代（软排笔＋去污粉）→ 第三代（镊子夹脱脂棉球蘸清水）。

工作台操作。定起手面 → 在三代工具里挑笔 → 调运笔力度 → 走完六道工序。做错会看到：力度出区间，竹黄面上仅存的墨迹被抹掉；双面有字不减速，那一面再也判不出有没有字。

  • q1 选择题+理由：竹黄面与竹青面相反性质背后的同一材料学原因；
  • q2 工程试错分析：三代工具演变表的补全——每一代解决了上一代的什么问题、又引入了什么新问题，「两全其美」的第三代为何能成立；

三绑夹与核对身份不能在工序之间掉线（轻量环节）

环节定位。一枚简从揭取到入库要经历多道工序、多次转手，「这枚简是谁、从哪来」的身份信息一旦掉线，它承载的历史信息就作废了。绑夹（把简固定在槽位里）与核对（编号系统）共同守护这条生命线。本环节是轻量环节，只设两道细问，不与其余环节强求对称。

关键数据。走马楼竹简存在两套编号：揭剥号（三段式「区—坨—序」，如30-27-38，记录揭取时的空间位置）与脱色号（顺序编号1～77731，按脱色批次给的）。报告明确「10546以后的竹简是先脱色再给编号」；存在两段空号：28051～30000、67851～70000——空号本身就是历史信息的指纹。

工作台操作。备棉线 → 选绑夹方式 → 送槽前按映射可信度排编号卡。做错会看到：选「不绑夹直接入槽」，当场复现2003年7月的漂移串槽事故——薄小的简随水流漂到别的槽里，编号混乱。

细问设计（2道）。

编号系统分析后果分析+方案设计
  • q1 编号系统分析：两套编号的语义差异、「先脱色再编号」与两段空号各自意味着什么，如何用编号系统重建一枚简的履历；
  • q2 后果分析+方案设计：复盘2003年漂移串槽事故——为什么会漂、为什么串的是薄小简、此后「单面绑夹」的设计解决了什么。
四饱水保存持续时间最长、失控风险最隐性

环节定位。简牍从地下取出后若任其干燥，会不可逆地收缩变形——必须立刻进入饱水状态，浸泡在药液里等后续处理。这一「等」以月为单位，失控风险（微生物侵害）却不会立刻显形，等你看见白斑时往往已经晚了。

关键数据。出土简牍含水率471%。防腐药剂筛选实验对比四种候选药剂（新洁尔灭、NaCl、麝香草酚、五氯酚钠等）在不同浓度下的抑菌表现：新洁尔灭在0.1%浓度下无法压制蚀斑病，提高到0.2%～0.3%后抑菌效果稳定有效。蚀斑病有三种侵害形态（黑斑、白斑、黏液状软腐），各自侵蚀速度与后果不同。

工作台操作。在六种药剂里选 → 配浓度 → 定换液周期 → 值守24个月（逐段推进，风险逐月兑现）。做错会看到：浓度压不住菌，第10个月长出白斑与黏液；再等一个周期，就是软腐。

细问设计（3道）。

假设排除题多维决策题排序+机理分析
  • q1 假设排除题：0.1%失效的四条可能原因（高含水率稀释药剂／药剂自身分解／代谢物中和／细菌抗药性），结合「提浓后有效」的证据逐一排除或保留——这是真实科研中的假说检验思维；
  • q2 多维决策题：依据四种候选药剂的实验数据表，在抑菌效果、药剂成本、操作安全之间做多维权衡选型；
  • q3 排序+机理：把蚀斑病三种侵害形态按危险度排序，并解释各自的作用机理。
五脱色从「能保存」进入「能使用」

环节定位。饱水保存解决「活下去」，脱色解决「能被读」。竹简深色本体与墨迹对比度极低，需要化学处理让底色变浅、字迹重新可辨。这是从保管走向研究的关键一跃。

关键数据。标准流程：1% EDTA二钠浸泡24小时 → 1%连二亚硫酸钠、保温45～50℃、作用20～40分钟。三种试剂的罗维朋测色数据（蓝色值越低脱色越好）；AAS法实测铁含量的「反常曲线」——低浓度时竹简中的铁反而高于对照组。有一类又宽又厚的刚竹简，标准流程处理完字迹仍模糊。

工作台操作。配EDTA → 选还原试剂 → 调恒温槽 → 按分钟保温作用。做错会看到：温度掉出45～50℃，罗维朋蓝色值停在高位不动；选了硼氢化钠，简几分钟后漂在液面上。

细问设计（3道）。

数据判读题反常数据解释决策题
  • q1 数据判读：三种试剂测色数据的比较与结论；
  • q2 反常数据解释：那条「低浓度反而升铁」的曲线是怎么回事——逼学生重构脱色机理；
  • q3 决策题：深色刚竹简的三个调整选项（提高EDTA浓度并延长浸泡／连二亚硫酸钠加倍／延长保温时间）——每个选项各有什么代价，选哪个、为什么。
六脱水不可逆程度最高的一道

环节定位。饱水简含水率高达数倍于自身重量，直接干燥会剧烈收缩变形（自然干燥实验：长度收缩20.4%、宽度收缩50.6%）。脱水定形的成败，直接决定这枚简最终能不能被释读、被研究——而它不可逆。

关键数据。自然干燥收缩率实测；抗张强度实测（GB/T453-2002，湖北省造纸质量监督检验站）；十六醇填充量为简牍本体重量的205%——填充物比竹材本体还重。标准脱水流程：乙醇置换50%×3天→75%×3天→100%×3天→100%再浸1天；十六醇置换50%×3天→75%（40℃烘箱）×3天→100%（58℃）×3小时。

工作台操作。判材质 → 选填充材料 → 控熔融温度 → 定填充量 → 干燥。做错会看到：填充不到位，宽度收缩率冲过5%的指标线，字跟着被压扁。

各向异性题数据计算+材料分析流程决策题

  • q2 数据计算+材料分析：从抗张强度与205%填充量两个数据反推十六醇法「替换法脱水」的材料学逻辑；
  • q3 流程决策题：一批混着薄简与厚刚竹简的简，标准流程只适用于3mm以内的薄简——两类简混批，你怎么办？

卷一 · 第五章虚拟仿真工作台：先动手，再被追问

5.1它不是动画，是可操作的因果机器

六个环节各有一台工作台，排在「关键数据」之后、「细问」之前。学生面对的不是一段播放的动画，而是一台每一步落手都立刻兑现后果的因果机器：排次序、挑工具、调参数、逐段推进，四项指标——简体完整度、字迹可辨度、信息完整度、累计工时——随操作实时跳动。

四种工步类型

工步类型学生做什么判定机制
pick · 选工具/做法从若干工具牌里挑一件（竹刀尖还是金属起子？三代笔里选哪代？）每个选项带 verdict（好/中/坏）与后果说明，个别选项明确标注「此步不可逆」

隐藏的第五指标：risk

面板上有四项指标，引擎里还有第五个不显示的量——累积操作风险。前面每一步的轻微失手都会往里累积，到「逐段推进」时一次性兑现成实际损伤。这模拟了真实修复中最阴险的规律：灾难往往不是最后一步造成的，而是前面每一步的小疏忽加总的结果。学生以为自己在第10个月「突然」看到了白斑，其实是第1个月选药剂时就埋下的祸根。

5.2画面即反馈：SVG 手工绘制的六种场景

仿真画面全部由 SVG 手工绘制（最大的一台约770个节点），不依赖贴图。逼真度来自四层功夫：

  • 材质——竹片弧面的横向渐变、纵向纤维纹、老化斑、编绳磨痕；
  • 笔墨——简面上每一笔是起收锋都收细的填充路径，底下垫一层洇墨；「墨迹可辨度」越低洇得越开，对应报告讲的「墨迹散淡」；
  • 光——湿面高光、器物投影、釉面反光；
  • 液体——液面起伏、水下折射、盘沿弯月面。
形制是硬约束。走马楼竹简长约23cm、宽1cm出头，长宽比接近1:19。画面上做了透视压缩，但「细长」这个第一印象必须保持——画成宽条就不是简了。每列字数按几何算出，字形才近方；脱水场景的字数按未收缩的尺寸计算，字才会随简体一起被压扁，视觉上「字跟着变形」。

六种场景各自可视化同一套指标：揭取台的简坨横截面、清洗台的泥污褪去、绑夹台的编号卡漂移、饱水槽的菌斑生长、脱色槽的温度计与罗维朋蓝色值、脱水台的收缩形变。每个工步都配专属动效——Flash 拍照、Droplets 点水、Steam 升温、Pour 下药、Debris 崩口、Ring 轻震——以一次性动作（cue 驱动、nonce 重挂即重放）与平滑状态过渡（transform/fill 过渡）两层实现，画面不再「跳」到新状态，而是「变」过去。全部动效受 prefers-reduced-motion 总开关管辖，照顾对动效敏感的用户。

5.3验收报告与操作记录

走完全部工步后出验收报告：四项指标结算、每一步的后果清单、以及报告里记载的实际做法对照。学生可以「重新开工」再走一遍，也可以点「把这次操作记录带给小简」——导师会针对代价最大的那一步开始追问，但仍然不代他复盘。

卷一 · 第六章数字人助教「小简」：位置感知与三档评阅

6.1两副面孔：常驻气泡与AI对话

小简只在环节页出场（大厅、登录页不见）。它有双形态：

  • 右下角常驻气泡：纯前端预设脚本（GuideAvatar + guide-lines），按学生实时位置——当前环节、读到的节序号（工序说明/关键数据/上机操作/细问）、完成记录——切换表情（微笑/讲解/思索/欢喜四态）与台词。台词同样只能出自报告，数字口径与正文一致；

上下文实时感知

小简知道你在哪：环节维度用 key=环节id 重挂清空重来；节维度订阅「已展开的节」，随每个请求把当前节名透传给服务端，系统提示词据此注入「学习者当前位置」。你在「上机操作」节问的问题，和在「细问」节问的问题，得到的引导侧重不同。

小简不主动说话。面板打开即空对话（空态提示「直接开口」），等学习者先开口；未开口前翻节也不推送隐藏通知。唯一的小简先发言场景，是学生在题卡上点「问小简这道题」——那本来就是学习者的明确提问动作。对话框收起即卸载（中止在途流），重开为空对话。这种克制是有意的：避免 AI 助教变成打扰源。

6.2知识库检索：让小简「有据可依」

小简背后挂着 wujian_knowledge 知识库数据集——三册走马楼相关扫描文献。学生在对话里提问时，服务端先检索知识库，命中后把扫描页以图片形式随用户消息交给多模态模型——模型是「看着原书页」回答的，这比纯文本检索的准确度与可信度都高一档。系统提示词同时约束：只用注入的报告数据回答，不编造数字与出处。

6.3「请小简评阅」：三档判定 + 流式解析

这是全工坊最核心的教学功能。每个答题框下方有「请小简评阅」按钮，学生写完答案点击后：

  1. 组装：前端把该框答案（含环节/题目/小问定位）交给服务端评阅接口；服务端用题干 + 教师预置的评阅要点（rubrics，按小问级存储、只走服务端不进浏览器包）+ 输出纪律组装评阅指令；
  2. 判定章：SSE 回流的第一帧是判定章——成立 / 部分成立 / 不成立（服务端从模型输出头部解析，正则优先匹配长词「部分成立」），像一枚盖章「啪」地落在答案上方；
  3. 流式解析：后续帧是逐字流出的解析正文，结构固定：点依据（答案里对的地方）→ 点缺口（差在哪、缺什么）→ 给一个能自己走下去的方向——绝不端出完整标准答案；
  4. 作废与重来：答案一改，旧判定立即在前端作废；学生可反复改稿、反复点评阅，直到满意。

评阅接口与对话接口同一套鉴权口径，限速桶独立（15次/分），防止滥用。

6.4确认提交与参考答案：闭环的最后一块

评阅通过后，学生点「确认提交」（两段式确认，先提示「提交后即定稿」）——输入锁定、评阅按钮隐藏、判定章保留，同时自动向服务端拉取参考答案（SSE 纯内容流）。参考答案每小问只生成一次：完整走完的成稿写入本地缓存，刷新重进直接读缓存，中途断开出错不缓存半成品。撰写纪律要求纯文本分点、不出现 markdown 语法与「参考答案」字样——它读起来像一位老师在你旁边娓娓道来，而不是一份冰冷的评分标准。

卷一 · 第七章简牍鉴赏展厅：竹木上的孙吴王朝

7.1陈列阅读：另一种认识文物的方式

如果说发掘篇教的是「怎么修」，鉴赏篇给的就是「修好了什么、为什么值得修」。它刻意采用博物馆陈列的形态：无解锁、无细问、无答题框、无小简——学生自由漫游，像走进一座安静的数字博物馆。这种形态上的「留白」本身就是设计：学习需要节奏，也需要喘息。

展厅首页（大厅「简牍鉴赏」页签）没有篇头，直接是五张板块入口卡。各板块独立成页，内容出自资料汇编《长沙走马楼吴简：种类、主题与释读》，逐段转录——这份材料的口径与发掘篇不同，所录释文均系转引（长沙简牍博物馆、简帛网及学者论文），页面上的声明一字不删。

7.2五大板块走读

壹 · 发现与归属：四说并存

1996年秋天的发现经过，与学界最关心的问题：这十余万枚简牍到底是什么性质的档案？页面并列四说——长沙郡机构档案说、郡县（侯国）文书混合说、临湘侯国（县级）文书档案群说、临湘侯国下属某机构说。汇编里标了「争论」的词条（丘与里、二年常限、算与事、真吏给吏、调等）一律保持诸说并列，绝不私自统一——学生在这里学到的第一课是：历史学的答案经常是「尚未定论」，而这正是它的魅力。

贰 · 形制六类：展签式的分类学

按形制分六类：大木简（嘉禾吏民田家莂——形制最大、单枚信息最完整的一类）、竹简（簿籍类，占出土绝大多数）、木牍（官文书牍、书信牍）、签牌·封检·封泥匣（文书制度的「包装物」）、名刺（三国的「名片」）、其他。每类配真实文物照片与展签式说明——分类学训练的是「从形制特征反推文书功能」的眼力。

叁 · 主题八类 + 丘里双轨

按内容分八大主题：田租赋税（嘉禾吏民田家莂）、户籍与人口、赋税征收簿书（口算钱、调布与杂税）、仓库出入（三州仓、州中仓与库钱库布）、司法文书、官吏与军政、名刺与书信、特殊身份简（真吏、给吏、复民、士伍……）。外加专题「行政层级与『丘』『里』双轨」——孙吴基层行政如何通过「丘」（居住地）与「里」（编户单位）双轨运转，这是理解全部簿籍文书的地基。

卷一 · 第十章教学价值与现实意义

10.1教学法价值：四重突破

其一 · 从「结论灌输」到「证据推理」

全部细问不预设结论，学生必须自己走完「证据→推理→判断」的全链路。排序题的「合法解不唯一」传递「考古证据允许多解」的学科科学观；反常数据解释题逼学生重构机理而非背诵规律——这是把科学思维的训练嵌进每一次作答。

其二 · 从「旁观」到「具身体验」

仿真工作台让学生以「修复师」身份承受决策的代价：力度出区间，墨迹没了；浓度压不住，白斑来了。犯错不再是扣分，而是看见后果——后果驱动的记忆远比说教深刻。而「重新开工」按钮保证试错零成本，这正是真实文物上不可能有的奢侈。

其三 · 从「抽样评价」到「全员、全程、全时」

AI评阅让每个学生、每道小问、每次修改都获得秒级反馈。评价标准由教师主权掌控（rubrics服务端存储，AI严格依此判定），反馈抵达速度却是教师手工批改永远做不到的——形成性评价第一次具备了全覆盖的工程条件。

其四 · 从「一锤定音」到「过程学习」

反复评阅—修改—再评阅的循环，加上参考答案在定稿后才解锁的时序设计，把「对答案」从作弊工具变成学习终点。进度可续支持长周期深度任务，尊重真实学习节奏。

10.2学科价值：一次「数字化转译」的完整示范

本工坊把一份几百页的考古技术报告，转译成了「可读（工序说明）、可算（数据反推）、可摸（仿真操作）、可问（AI助教）、可评（智能评阅）、可留（进度成就）」的六维教学形态。这个转译过程沉淀的方法论——内容纪律、口径备案、仿真与评阅的分工纪律、AI幻觉治理——对任何文博类、乃至任何「重内容」学科的教学数字化转型，都是可复用的参考。

10.3文化价值：让沉睡的档案变成活跃的现场

1996年那口古井里的十万枚简牍，记录的是一千七百年前一个基层政权的柴米油盐：谁家交了多少税、仓里进了多少米、一个贪腐小吏如何落网。本工坊做的事，是让这批「沉睡的档案」重新变成「活跃的教学现场」——每一个走进工坊的学生，都在某种意义上参与了那场跨越千年的接力：前辈从井里把简取出来，今天的学生在屏幕前学会理解「为什么这样修」，明天他们中的一些人会走进真正的库房。

卷二 · 序章一口古井，一场大雨

故事要从1996年秋天讲起。

那一年，长沙市中心，五一广场走马楼西侧，平和堂商厦的工地正在打地基。混凝土搅拌机的轰鸣里，一口古井塌出了缺口——工人们凑近看，井里没有金银，没有青铜，只有一团一团湿黑的、说不上是什么的东西，层层叠压，像被岁月揉皱又攥实的纸团。

考古队来了。清点、揭取、整理，数字最终定格在一个让所有人屏息的量级上：简牍总数超过十万枚，超过此前全国出土简牍的总和。

这是三国孙吴时期的行政文书。赋税簿、户籍册、仓廪账、司法案卷、官吏名刺……一千七百年前，一个基层政权的柴米油盐、钩心斗角与人间烟火，被一场大火或一次掩埋封进井底，从此避开光线、氧气与时间，原封不动地等到了1996年。

学界后来给它许多称号：「二十世纪中国最重要的考古发现之一」「埋在地下的孙吴档案库」。但对当时的文物修复人员来说，喜悦之外是一个近乎残酷的现实：这十万枚简牍，每一枚都湿软如煮过的面条，含水率471%——比鱼还「水灵」。任其干燥，它们会剧烈收缩、扭曲、开裂，字迹随之永远消失；放进库房静置，微生物几个月内就会把竹纤维啃成软腐的黏液。

从井底到书页，这批简牍要走六道工序：揭取、清洗、绑夹与核对、饱水保存、脱色、脱水。每一步都是与物理、化学、生物学的贴身搏斗；每一个决策——用竹刀还是金属起子、浓度0.1%还是0.2%、温度45℃还是58℃——都直接决定一枚简牍的生死。

而这些决策的依据、数据、教训与经验，全部沉淀在一份几百页的技术报告里：《长沙走马楼三国吴简的保护与整理》。

现在，这份报告被打开成了一座工坊。

报告里的每一个数字、每一条约束、每一次事故，都被如实搬了进来——包括那场2003年因「不绑夹直接入槽」而酿成的漂移串槽事故。在这座工坊里，你将以修复师的身份，把六道工序亲手走一遍。你可以犯错，可以重来，可以在四项指标全线飘红时咧嘴一笑，再点一次「重新开工」——而真正的国宝，一失误就是永别。这就是这座工坊存在的意义：让你在零成本的地方，学会价值连城的判断。 —— 走马楼吴简修复工坊

卷二 · 第二章第一道工序 · 揭取：不可重来，所以更要好好来

「揭取——唯一一道不可重来的工序。」这不是吓唬你，这是考古的规矩。

井底的简牍不是散乱的，它们成坨叠压、卷成筒状——哪坨压着哪坨，记录的是它们被放进井里的原始顺序。这层「层位关系」是日后恢复简册编联顺序的唯一钥匙：揭取时每揭一坨都要记录叠压关系，一旦揭乱，钥匙就断了，永远接不回来。

走进环节一，你先读到的不是口号，而是报告里的原始记录：I区的叠压关系 a→b→c、b→d、d→e，c坨自身还分 c①→c②→c③……然后，细问来了——给你这组记录，请你排出揭取的次序。

注意，这题没有「唯一正确答案」。任何满足先后约束的排列都算对——因为考古证据本来就允许多解。真正区分高手与新手的是另一个问题：哪些单位对的次序，从现有证据里根本判不出来？指不出这些「不可判定」，才是这道题的失分点。

然后你上揭取工作台。五个简坨横在你的屏幕上，横断面的缝清晰可见。你排次序——排错了，层位信息当场作废，指标「信息完整度」哗地掉下去；你选刀——竹刀尖还是金属起子？金属起子效率高，但会在简上留下永久的划伤，「简体完整度」替你记住这一切；你定步距——报告写的是每2～3厘米停看一次，步子迈大了，简会断在半空，这一步标注着四个字：「此步不可逆」。

最后是一道机理分析题：报告揭示了一条奇妙的规律——每枚简端平的一面是有字正面、弧形面是背面；上半部分有字面朝下，下半部分正好相反。当年的工作人员就是靠这条规律，按编绳磨痕复制新竹片、编联成册、模拟卷起，用横断面反推出了原始卷圈顺序。你要做的，是把这套推理的链条自己走一遍。

卷二 · 第三章第二道工序 · 清洗：让文字第一次真正可见

泥壳剥开的那一刻，有些字第一次见到了光——也可能，是最后一次。

出土的简牍裹着泥污，字迹完全不可见。清洗是它们与文字的第一次重逢，但重逢之路布满陷阱：竹黄面「吸墨渗透好，但耐磨强度低」——你手上力道重一分，那仅存的墨迹就淡一分。这不是比喻，是材料学事实，而且和竹青面的性质「组织致密、不易书写、但字迹耐磨持久」出自同一个原因。什么原因？第一道细问你来回答。

报告还记录了工具的三代演变：第一代用粗排笔和毛刷，快，但伤字；第二代换成软排笔加去污粉，温和些，但去污粉残留；第三代定型为「镊子夹脱脂棉球蘸清水」——一锤定音。第二道细问问你：补全这张演变表，并回答，每一代解决了上一代的什么问题、又引入了什么新问题？工程没有完美，只有权衡——这道题教的就是这个。

然后是让人头皮发麻的数字：竹简共73631枚，每枚清洗耗时40～50分钟，每天工作10小时、每月22个工作日。第三道细问请你反推：全部清洗完需要多久？如果人力减半呢？拿出计算器，算出「年」这个单位——你会突然理解，文物保护为什么是一项以「年」计的事业。

清洗工作台上，你要亲手定起手面（先洗哪一面？）、在三代工具里挑笔、调运笔力度（滑杆上有报告给的安全带，出带报警、偏得越远代价越大）、走完取简→开卡入槽→清理污物→清理字面→脱色前清洗→再清洗的六道工序。屏幕上，泥污随着你的运笔一圈圈褪去，字迹一点点浮现——那种「拂去千年尘埃」的体感，是任何幻灯片都给不了的。

对了，这一环节还藏着一个惊喜：画图题。拿起画笔，画出简册卷起时的横断面示意图。你画的不是给老师看的——是给AI看的：多模态模型会「看」你的图，按评阅要点判断它是否完整。画错了它会告诉你缺了什么，画对了，那种被机器「看懂」的感觉，值得一试。

卷二 · 第四章第三道工序 · 绑夹与核对：一枚简的身份证明

工序是流水线，身份不能掉线。掉线的那枚简，字再清楚也成了「来历不明」。

一枚简从揭取到入库，要转手十几次、历经数月。「它是谁、从哪个坨来的、排在第几」——这套身份信息靠两套编号系统守护：揭剥号（三段式「区—坨—序」，如30-27-38，记录它出土时的空间坐标）与脱色号（顺序编号1～77731，按脱色批次给的）。

细问一的题干像一道侦探题：报告明确「10546以后的竹简是先脱色再给编号」；编号序列里还存在两段空号：28051～30000、67851～70000。空号意味着什么？两套编号对不上的简，怎么追回它的履历？把这道题答下来，你会获得一种文物工作者特有的敏感：对「来历」的较真。

细问二是一次事故复盘——真实发生过的那种。2003年7月，第三批次脱色，工作人员用特制脱色槽，把单根竹简不绑夹直接放入槽内。结果：薄小的简随水流漂移到其他简的槽里，编号一片混乱，此后全部改为单面绑夹。你的任务：分析事故成因（为什么漂的偏偏是薄小简？）、评估后果（编号混乱意味着什么）、并设计后续方案。

工作台会把这个事故「复现」给你看：如果你也选「不绑夹直接入槽」——恭喜，2003年7月的场面重演，指标「信息完整度」当场跳水。屏幕不会骂你，但那一串跳红的数字，比任何批评都让人长记性。

卷二 · 第五章第四道工序 · 饱水保存：与时间对坐二十四个月

这一环节的敌人看不见、不着急、但从不迟到。它的名字叫：微生物。

清洗完的简不能晾着——干燥就是变形。它们要泡进药液，以「饱水」状态等待后续处理。这一等，以月为单位；而药液里的微生物，一刻也没闲着。等你看见白斑、黏液的时候，往往已经是软腐的前夜。

报告记录了一次真实的科研困局：新洁尔灭在0.1%浓度下压不住蚀斑病。研究人员提出四条可能原因：①简体471%的含水率稀释了药剂，实际浓度低于标称；②药剂在水中自己分解失效；③细菌代谢物中和了药效；④细菌产生了抗药性。后续实验把浓度提到0.2%～0.3%，抑菌效果稳定有效。

细问一就是这道「假设排除题」：四条假说，结合「提浓后有效」这条证据，逐一排除或保留。这是生物医学研究的标准思维范式——假说检验——被原汁原味地搬进了课堂。细问二接着上强度：四种候选药剂的实验数据表摆在你面前，抑菌效果、药剂成本、操作安全多个维度互相牵制，你来选型，说明理由。细问三要求把蚀斑病的三种侵害形态按危险度排序，并解释各自机理。

饱水工作台是六台里最「熬人」的一台：选药剂（六选一）、配浓度、定换液周期，然后——值守24个月。逐月推进的进度条上，前9个月可能风平浪静；第10个月，如果你的浓度没压住菌，白斑和黏液会在简面上肉眼可见地长出来。要不要马上换药？换药要不要停工期？每多等一个周期，风险都在复利。这台工作台教的不是化学，是「隐性问题管理」——工程世界里最贵的一课。

卷二 · 第六章第五道工序 · 脱色：从能保存，到能使用

饱水保存让简「活着」，脱色让简「被读」。这一步，是保管与研究的分水岭。

饱水简的底色深，墨迹浅，对比度低到几乎不可辨。脱色用化学手段让底色变浅、字迹重新浮出——标准流程精确到分钟：1% EDTA二钠浸泡24小时，然后1%连二亚硫酸钠、保温45～50℃、作用20～40分钟。

为什么是这个配方、这个温度、这个时长？细问一给你三种试剂的罗维朋测色数据（蓝色值越低，脱色越好），请你判读；细问二甩给你一条「反常曲线」——AAS法实测，处理液中的铁随浓度升高单调递增（正常，铁被脱出来了），但竹简里的铁在低浓度时反而比没处理的还高，到0.5%以后才开始下降。请你解释这条曲线。提示：想想EDTA先螯合了什么、后螯合了什么。这道题是全工坊化学机理的天花板，答出来的那一刻，你会觉得自己像做了半天的科研。

细问三是一个「疑难杂症」：一枚又宽又厚、颜色特别深的刚竹简，标准流程走完，字迹仍然模糊。三个选项：A. EDTA浓度提到2%、浸泡延到72小时；B. 连二亚硫酸钠加倍；C. 保温时间延长到60分钟。每个选项都有代价——你选哪个？为什么？（真实修复界没有「全都要」。）

脱色工作台上，配EDTA、选还原试剂、调恒温槽、按分钟保温——温度计就悬在画面上方，罗维朋蓝色值随温度实时变化。温度掉出45～50℃，蓝色值停在高位不动；手滑选了硼氢化钠——几分钟后，你的简漂在了液面上。那一刻你会明白，为什么报告要把温度区间写进标题里。

卷二 · 第七章第六道工序 · 脱水：定形，最后一关

饱水简的含水，比自身还重。要把水「换」出去而不让简「缩」回去——人类花了多少年，才找到那管十六醇。

先看一个让人倒吸凉气的数字：自然干燥实验里，走马楼饱水竹简干燥至重量稳定后，长度平均收缩20.4%，宽度平均收缩50.6%。宽度缩一半——字就全毁了。直接晾干这条路是死的，必须「置换脱水」：先用乙醇把水换出来，再用十六醇把乙醇换出来，让支撑物留在竹纤维里替水「撑住」简体。

报告里的两个硬核数据撑起了细问二：十六醇填充量达到简牍本体重量的205%——填充物比竹材本体还重；抗张强度实测按国家标准GB/T453-2002、由湖北省造纸质量监督检验站出具。从这两个数据反推「替换法脱水」的材料学逻辑，你会真正读懂「205%」这个数字的含义——那不是 extravagance，那是让简「不塌」的物理代价。

细问一问各向异性：为什么长度只缩两成、宽度却缩五成？答案在竹材的细胞结构里——纤维纵向排列，纵向有「骨架」撑着，横向没有。细问三是流程决策：一批混着薄简（3mm以内，标准流程适用）与又宽又厚的刚竹简——混批怎么办？分批的话按什么分？这是真实修复方案设计题。

脱水工作台上最揪心的画面：填充不到位时，屏幕上的简眼看着「瘦」下去——宽度收缩率冲过5%的指标红线，简上的字被压得变形。那一刻，「不可逆」三个字有了形状。

卷二 · 第八章你的搭档：小简，一位从简牍里走出来的助教

六道工序走下来，你不会是孤军奋战。你的右下角，一直住着一位搭档。

它叫小简——数字人向导，只在环节页出场。它不吵不闹，就待在那儿；你翻到哪一节，它的表情和台词就换到哪儿：你刚开始读工序说明，它微微一笑陪你入门；你对着数据表皱眉，它也摆出思索的表情；你完成了一道细问，它眉眼弯弯替你高兴。四副表情——微笑、讲解、思索、欢喜——对应你在工坊里的每一段旅程。

点它，对话框就展开。你可以问它任何与内容相关的问题：「为什么竹黄面更容易吸墨？」「两段空号到底是怎么回事？」「这道题我卡住了，能给我个提示吗？」——它背后站着三册走马楼文献的扫描知识库，检索命中时，它是看着原书页回答你的，不编数字、不造出处；报告里口径有出入的地方，它还会主动告诉你「这里学界有两种说法」。

它知道你在哪。你在「上机操作」节问的问题，和你在「细问」节问的问题，它给的引导侧重不一样——因为每一次对话请求都带着你的位置信息。它甚至知道你的进度：哪道题你还没答，它绝口不提答案；哪道题你答完了，它才愿意跟你复盘。

它评阅你的答案。每个答题框下方都有「请小简评阅」按钮。点下去，几秒后一枚判定章落在你的答案上——成立、部分成立、或不成立——接着解析逐字流出：先说你的答案里对在哪，再说缺了什么，最后给一个能自己走下去的方向。它从不端出标准答案。答案改了，判定自动作废；你可以一遍遍改、一遍遍请它评，直到自己真正想明白。想明白了，点「确认提交」，定稿、锁定，参考答案这才姗姗来迟——像一个耐心的老师，永远等你先交卷。

「小简不说教、不泄题、不代答。它只是恰好知道那口古井里发生的一切，并且永远有空。」

卷二 · 第十章五种题型：你的每一次作答，都是一次专业判断

本工坊没有一道「选 C」就完事的题。十七道细问，五种作答形式，对应五种思维方式：

排序题 · 拖出层序

把对象拖进层，层内并列、层间递进。它不考你「背没背住标准顺序」，考你「能不能从约束条件推出合法解」——以及，敢不敢承认「这几对判不出来」。

判断题 · 逐条对决

五条陈述，逐条判正误。判「错」要写出正确表述，判「对」要说明它对后续工序意味着什么——判断从来不是终点，论证才是。

多选题 · 论证排除

勾出所有可行项，并说明理由。多选题的真正考点是「为什么其他的不行」——排除法，是工程师的基本功。

匹配题 · 连线成网

左边的药剂，右边的作用路径，一一连线。连完，一张化学知识的网就在你脑子里织好了。

画图题 · 让AI看懂你

画笔、橡皮、撤销，画出一幅横断面示意图。交卷对象是多模态大模型——它会真的「看」你的图。这是全工坊最未来的一道题。

而所有这些作答——无论拖拽、勾选还是画图——都可以一键「问小简」或「请小简评阅」。你和小简看到的，永远是同一份作答。

各位好。在正式开始之前，我想先讲一个故事——一口井的故事。

1996年10月，长沙市中心，五一广场走马楼西侧，平和堂商厦的工地上，机器轰鸣。打地基的时候，一口古井塌出了缺口。工人们凑过去看：井里没有金银，没有青铜，只有一团一团湿黑的、说不清是什么的东西，层层叠压在一起。

考古队很快赶到了。清点、揭取、整理——最后得出的数字，让所有人屏住了呼吸：简牍，超过十万枚。超过此前全国出土简牍数量的总和。

这是三国孙吴时期的行政文书。赋税簿、户籍册、仓廪账、司法案卷、名刺书信——一千七百年前一个基层政权的柴米油盐，原封不动地，沉睡在一口井里。

但对修复人员来说，喜悦之外是一个残酷的现实：这十万枚简牍，每一枚都湿软如煮过的面条，含水率高达百分之四百七十一。任它干燥，会剧烈收缩、开裂，字迹永远消失；放进库房静置，微生物几个月内就会把竹纤维啃成黏液。

从井底到书页，这批国宝要走六道工序：揭取、清洗、绑夹与核对、饱水保存、脱色、脱水。每一步的判断，直接决定一枚简牍的生死。

而今天要给大家介绍的，是一座把六道工序完整搬进浏览器的「修复工坊」。在这里，每个人都能亲手把一枚简，从井底修到能被阅读。我们的身份不是观众——是修复师。

好，进工坊看看。输入邮箱和密码——我们进去。

卷三 · 第三幕六道工序巡礼

03环节一
画面：环节一「揭取」页面
环节页顶部是环节名「一 · 揭取」与它的口号「唯一一道不可重来的工序」。页面分节展开：为什么必须有这个环节（含叠压关系数据）→ 上机操作 → 细问。

环节一，揭取。它的口号有点吓人：「唯一一道不可重来的工序」。

为什么不可重来？因为井底的简牍不是散乱的，它们成坨叠压——哪坨压着哪坨，记录的是它们被放进井里的原始顺序。这层「层位关系」，是日后恢复简册编联顺序的唯一钥匙。揭取时每揭一坨都要记录叠压关系；揭乱了，钥匙就断了，永远接不回来。

看屏幕上的数据：I区记录到的叠压关系——a压b、b压c、b压d、d压e，c坨自己还分三小坨。第一道细问就是给你这组记录，让你排出揭取的次序。

这里有个值得说的设计：这题没有唯一正确答案。任何满足先后约束的排列都算对——因为考古证据本来就允许多解。真正的高手，是能指出「哪几对的次序从现有证据里根本判不出来」。工坊教的第一课，就是诚实面对证据的边界。

往下看，「上机操作」——揭取工作台。五个简坨，横断面，清清楚楚。排次序、选工具（竹刀尖，不是金属起子——金属会在简上留下永久划伤）、定步距——报告写的是每两到三厘米停看一次。步子大了会怎样？简断在半空，这一步标着四个字：「此步不可逆」。四项指标——简体完整度、字迹可辨度、信息完整度、累计工时——随每一步落手实时跳动。

在这儿犯错不花钱——但每一分代价，屏幕都替你记着账。这就是仿真的意义：在零成本的地方，学会价值连城的判断。

04环节二
画面：环节二「清洗」页面，含工具三代演变表与工时数据
「关键数据」节里出现工时统计：竹简共73631枚、每枚40～50分钟、6道工序、每天10小时。表格里是三代清洗工具的演变。

环节二，清洗——「让字迹第一次真正可见」。

出土的简裹着泥壳，字迹完全看不见。清洗是文字与光的第一次重逢——但重逢之路有陷阱：竹黄面吸墨好、但耐磨强度低，你手上重一分，仅存的墨迹就淡一分。

这页有张表特别值得看——清洗工具的三代演变。第一代粗排笔毛刷，快，但伤字；第二代软排笔加去污粉，温和些，但去污粉有残留；第三代定型为镊子夹脱脂棉球蘸清水。工坊的细问不是让你背这三代，而是问你：每一代解决了上一代的什么问题、又引入了什么新问题？——工程没有完美，只有权衡。

再看这几个数字：竹简共73631枚，每枚清洗40到50分钟，每天工作10小时、每月22个工作日。细问请你反推：全洗完要多久？人力减半呢？算出来的单位是「年」。学生亲手算过一遍，才会真正理解文物保护为什么是以「年」计的事业。

清洗工作台上，你可以亲手调运笔力度——滑杆上有报告给的安全带，出带报警、偏得越远代价越大。泥污随你的运笔一圈圈褪去、字迹一点点浮现，「拂去千年尘埃」的体感，是在幻灯片里得不到的。

05环节三
画面：环节三「绑夹与核对」页面，两套编号系统示意与2003年事故复盘题
细问二题干展示：2003年第三批次脱色，「不绑夹直接入槽」导致薄简漂移串槽、编号混乱。

环节三，绑夹与核对——「身份不能在工序之间掉线」。这是个轻量环节，但藏着全工坊最有「侦探味」的两道题。

一枚简从揭取到入库要转手十几次。它的身份——从哪个坨来、排第几——靠两套编号系统守护：揭剥号，三段式「区—坨—序」，记录出土时的空间坐标；脱色号，按批次顺序编的一到七万七千七百三十一。细问一给你几个线索：报告明确「10546以后先脱色再编号」；编号序列里还有两段空号——28051到30000、67851到70000。空号意味着什么？怎么追回一枚「身份掉线」的简的履历？这就是学生要答的。

细问二是一次真实事故的复盘：2003年7月，工作人员把单根竹简不绑夹直接放进脱色槽——结果薄小的简随水流漂到别的槽里，编号一片混乱。此后全部改为单面绑夹。学生要分析成因、评估后果、设计方案。在工作台上如果你也选「不绑夹直接入槽」——2003年7月的场面当场重演，信息完整度跳水。屏幕不骂人，但跳红的数字比批评更让人长记性。

06环节四
画面：环节四「饱水保存」页面，四种候选药剂实验数据表
数据表列出各药剂在不同浓度下的抑菌表现；旁边是蚀斑病三种侵害形态的介绍。

环节四，饱水保存——「持续时间最长、失控风险最隐性」。

清洗完的简要泡进药液，以饱水状态等后续处理。这一等以月为单位，而药液里的微生物一刻不停。等你看见白斑和黏液，往往已经是软腐的前夜。

这页的报告数据记录了一次真实的科研困局：新洁尔灭在0.1%浓度下压不住蚀斑病。研究人员提出四条可能原因——含水率471%的简体稀释了药剂？药剂自己分解了？细菌代谢物中和了药效？还是细菌有了抗药性？后续把浓度提到0.2%到0.3%，效果稳定有效。

细问一就是这道「假设排除题」：四条假说，结合「提浓有效」这条证据，逐一排除或保留。这是生物医学研究的标准范式——假说检验——被原汁原味搬进了课堂。

饱水工作台是六台里最「熬人」的一台：选药剂、配浓度、定换液周期，然后值守24个月。前9个月可能风平浪静；第10个月，如果你的浓度没压住菌——白斑和黏液会在简面上肉眼可见地长出来。要不要马上换药？换药要不要停工？每多等一个周期，风险都在复利。这台工作台教的不只是化学，是隐性问题管理——工程世界里最贵的一课。

07环节五
画面：环节五「脱色」页面，罗维朋测色数据表与AAS铁含量反常曲线
细问二的题干给出：处理液铁含量单调递增，竹简铁含量在低浓度反而高于对照组的「反常曲线」描述。

环节五，脱色——「从『能保存』进入『能使用』」。饱水保存让简活着，脱色让简被读。

标准流程精确到分钟：1%的EDTA二钠浸泡24小时，然后1%连二亚硫酸钠，保温45到50摄氏度，作用20到40分钟。为什么是这个配方、这个温度？细问一给你三种试剂的测色数据，请你判读。

细问二是全工坊化学机理的天花板，我特别想给大家念一下——AAS实测铁含量：处理液里的铁随浓度升高单调递增，正常，铁被脱出来了；但竹简里的铁，在低浓度时反而比没处理的还高，到0.5%以后才开始下降。请你解释这条反常曲线。学生答出这道题的那一刻，等于把EDTA螯合、脱色机理自己推了一遍——科研的滋味，就在这里。

脱色工作台上，温度计悬在画面上方，蓝色值随温度实时变化。温度掉出安全带，蓝色值停在高位不动；手滑选了硼氢化钠——几分钟后，你的简漂在了液面上。

08环节六
画面：环节六「脱水」页面，自然干燥收缩率数据与标准脱水流程
关键数据展示：长度收缩20.4%、宽度收缩50.6%；十六醇填充量205%；标准流程的乙醇/十六醇置换梯度表。

最后一道，脱水——「不可逆程度最高的一道」。

先看一个倒吸凉气的数字：自然干燥实验里，饱水竹简干燥后长度平均收缩百分之二十点四——宽度，收缩百分之五十点六。宽度缩一半，字就全毁了。所以直接晾干这条路是死的，必须「置换脱水」：先用乙醇把水换出来，再用十六醇把乙醇换出来，让填充物留在竹纤维里，替水撑住简体。报告里的数据很硬：十六醇填充量达到简牍本体重量的一百零五分之一百零三——也就是205%，填充物比竹材本体还重。这个数字不是浪费，是让简「不塌」的物理代价。

细问一问各向异性：为什么长度只缩两成、宽度缩五成？答案在竹材细胞结构里——纤维纵向排列，纵向有骨架，横向没有。细问三是真实方案设计：一批混着薄简和厚刚竹简，标准流程只适用薄简——你怎么办？

脱水工作台上最揪心的画面：填充不到位，屏幕上的简眼看着瘦下去，宽度收缩率冲过5%的指标红线，字跟着被压扁。「不可逆」三个字，在这一刻有了形状。

六道工序走完——从井底到书页，从泥坨到文字。这，就是走马楼吴简的第二次生命。

卷三 · 第四幕鉴赏展厅

09展厅
画面：切到「简牍鉴赏」页签，展厅首页五张板块入口卡，随后进入案例精读页
五张入口卡：壹 发现与归属、贰 形制六类展签、叁 主题八类+丘里双轨、肆 案例精读、伍—捌 术语·出版·意义·来源。镜头扫过案例四「许迪割米案」。

修完了简，来读一读简上写的是什么。切到「简牍鉴赏」——一座安静的数字博物馆。这里没有解锁、没有细问、没有指标，只有五块展区和一千七百年的时光。

「发现与归属」展区里，四说并列：这批简到底是谁的档案？长沙郡的？郡县混合的？还是临湘侯国的？——学界至今没有定论。这里教学生的是：历史学的答案，常常是「还没有答案」，而这正是它的魅力。

「形制六类」练的是眼力：大木简、竹简、木牍、签牌封检、名刺——看形制，猜功能。「主题八类」把孙吴基层社会的全景铺开：田租、户籍、口算钱、仓廪、司法、军政。

我特别想给大家看「案例精读」——五枚简，五个切口。其中案例四，许迪割米案：一场三国基层贪腐案的完整司法档案，从检举、审讯到判决——一枚简串起一部微型司法剧。还有案例一，南彊丘聂仪莂：一枚大木简上，一户人家一整年的税，白纸黑字。还有名刺——三国人的拜帖，上头的客套话，和今天如出一辙。

值得一提的是图版的纪律：这里所有照片都是真实文物照，每张带署名；而发掘篇的配图是AI示意图，图题都以「示意」开头——两种图，从不冒充彼此。这座博物馆，连「诚实」都是展品。

卷三 · 第五幕小简登场

10小简
画面：回到任一环节页，右下角小简立绘与气泡；点击立绘展开对话框，输入一个问题，答案流式输出
小简立在右下角，气泡随页面位置切换台词。点击后对话框展开，演示者输入「为什么竹黄面更容易吸墨？」，小简的回答逐字流出。

现在介绍这位——它一直站在角落里，大家可能已经注意到右下角这位小家伙了。它叫小简，工坊的数字人助教。

小简不吵不闹，就待在那儿。你翻到哪一节，它的表情和台词就换到哪儿：你读工序说明，它微笑；你对着数据皱眉，它也跟着思索；你完成一道细问，它眉眼弯弯替你高兴。它知道你在哪——每一次对话请求都带着你的位置信息。

点它，对话框展开。可以问它任何内容相关的问题——我问一句：「为什么竹黄面更容易吸墨？」看，回答是逐字流出来的。

更重要的是它背后站着的东西：三册走马楼文献的扫描知识库。检索命中时，它是看着原书页回答你的——不编数字、不造出处；报告里口径有出入的地方，它还会主动告诉你「这里学界有两种说法」。

它还有个「绝活」——评阅。我们看下一幕。

卷三 · 第六幕五种题型与智能评阅

11题型
画面：依次展示五种题型页面——排序题（拖拽入层）、判断题（逐条）、多选题、匹配题、画图题
演示模式自动点击题号按钮切换五种题型。画图题页面上，canvas 画板展示简册横断面示意。

工坊一共17道细问，但作答形式不止问答一种——一共五种，每种对应一种思维方式。

排序题：把对象拖进层，层内并列、层间递进——考的是从约束推合法解，以及敢不敢承认「这几对判不出来」。

判断题：五条陈述逐条判正误，判错要写正确表述、判对要说明它意味着什么——判断从来不是终点，论证才是。

多选题：勾出所有可行项还要说明理由——真正的考点是「为什么其他的不行」。

匹配题：左边药剂、右边作用路径，连线成网。

最特别是画图题：拿起画笔画横断面示意图——而「看」你这张图的，是AI。多模态模型按评阅要点判断图的完整性。画错了它会告诉你缺什么。让AI看懂你画的图——这是全工坊最未来的一道题。

12评阅
画面：某答题框写入答案，点击「请小简评阅」——判定章落下，解析流式输出；随后点「确认提交」，参考答案生成
答案框上方出现朱砂色判定章「部分成立」；解析逐字流出，结构为「点依据→点缺口→指方向」。

现在看全工坊最核心的功能——智能评阅。

我在这个答题框里写了一份答案，点下方的「请小简评阅」——看，几秒钟，一枚判定章落在答案上：「部分成立」。接着解析逐字流出，结构是固定的三段：先说我答对了什么，再说缺了什么，最后给一个能自己走下去的方向。

注意——它从不端出标准答案。这是写进系统提示词的硬纪律：学生没给答案之前，不给答案、不给要点；计算题只给数字的退回重做。评阅标准本身由教师逐题编制、存在服务端，AI严格照此判定——评价的主权在老师，抵达的速度在秒级。

答案可以反复改，改了旧判定自动作废，可以一遍遍请它评——直到自己真正想明白。想明白了，点「确认提交」：定稿、锁定，参考答案这才生成出来。像一个耐心的老师，永远等你先交卷。

对老师这意味着什么？大班教学里最痛的「开放题没法逐份批」——这里第一次具备了全覆盖的工程条件。每个学生、每道小问、每次修改，都有秒级反馈。

B现场高频问答预案

Q1 · 「这些题目和答案，是AI编的吗？」

A：不是。全部17道细问从《长沙走马楼三国吴简的保护与整理》的原始数据反向设计；评阅要点由教师逐题编制、存储在服务端，AI只负责依据要点判定与表述解析。报告不同章节口径有出入的六处，工坊在大厅「报告内部数字出入备案」里逐条列明——较真到这个程度，就是为了内容的可信。

Q2 · 「AI评阅会不会评错？」

A：会「不完美」，但设计上控制了它的危害边界。判定是三档制而非打分制，天然降低误判的表面冲击；解析结构固定为「点依据—点缺口—指方向」，即使判定有偏差，学生仍能从解析里获得可自查的信息；而且评阅可以反复触发、答案可修改——它更接近一位「随时在场的助教」，而非「终审法官」。教师主权在评阅要点，随时可以修订。

Q3 · 「仿真里的失败后果是真实的吗？」

A：工具、参数区间、失败机制全部出自报告——比如45～50℃的脱色温度、2～3厘米的揭取步距、2003年漂移串槽事故，都是真实记载。唯一的「教学设定」是指标扣分幅度，起始屏和结算页都写明了这一点。我们不把教学权重伪装成报告数据。

Q4 · 「学生直接问AI要答案怎么办？」

A：问不出来。这是写进系统提示词的硬纪律——「先答后评」：学习者没给答案之前，不给答案、不给要点。AI会被引导反问、给提示、给方向，但不会代答。参考答案只有在学生点「确认提交」定稿之后才生成。防作弊的最好办法不是封锁，是时序设计。

Q5 · 「适合什么课程用？」

A：文博与文物保护类课程是直接对口；考古学、历史文献学可用鉴赏篇与编号系统、卷圈复原等内容；材料化学可用脱色、脱水两环节（螯合反应、置换、各向异性）；甚至工程管理课程也能用工时反推、隐性风险管理的内容。六环节是一个「素材富矿」，各学科各取所需。

Q6 · 「需要什么设备与环境？」

A：一台能跑现代浏览器的设备即可，桌面端体验最佳（画板题、排序题在触屏上也可用，移动端深度适配在迭代计划中）。注册一个邮箱账号，进度就跟着账号走。无需安装任何插件。

卷四 · 第四章内容层设计：单一事实源

4.1结构化内容模型

六环节内容全部收敛在 content.ts 的类型化常量里。每个环节 = 元信息 + 三~五个「节」（section）；每个细问 = 题干 + 作答形式（5 种题型）+ 协议文本生成器 + 评阅要点引用。举一道排序题的结构为例：

{
  id: "1-q1",
  kind: "ordering",              // 排序题
  section: "细问",                // 归属节
  stem: "依据 I 区叠压关系，给出揭取次序……",
  items: ["a","b","c","d","e"],   // 可拖对象
  constraints: ["a→b","b→c","b→d","d→e","c①→c②","c②→c③"],
  serialize: (result) => `排序：${result.layers.map(l => l.join("、")).join(" → ")}`,
  rubricId: "1-q1"               // 指向 rubrics.ts
}

关键设计：所有作答最终序列化为纯文本协议（「排序：a → b、c → d」/「多选：A、C」/「匹配：A→②」/「作图：[base64 PNG]」）。文本、排序、选择、多选、匹配五类作答在存储、评阅、问小简三条通道里形态完全一致——下游系统无需为题型写特判。画板题的 base64 图片单独走多模态通道，但判定回填同一 schema。

4.2内容纪律：三道防线

  • 出处纪律：关键数据节标注报告章节号；展厅释文逐段转录并声明「转引」来源；六处报告内部数字出入在大厅设「备案」页逐条列明，不私改原文；
  • 口径纪律：内容「是什么就是什么」——不简化、不夸张、不为了「教学友好」牺牲准确性；仿真里唯一的教学设定（指标扣分权重）在起始屏与结算页双声明；
  • 图版纪律：真实文物照（带 credit 字段）与 AI 示意图（图题以「示意」开头）严格分野，绝不同页混用。

卷四 · 第五章AI 能力矩阵：评阅、问答与幻觉治理

5.1小简问答链路（RAG）

用户提问（含位置信息：环节/节/题号）
   │
   ▼
/api/guide ──► 构造系统提示词（角色 + 先答后评纪律 + 作答协议说明）
   │              + 学生当前作答（若有）+ 位置上下文
   ├──► RAG 检索：三册走马楼文献扫描件 → 命中段落
   ▼
豆包 chat（流式）──SSE──► 前端逐字渲染
   │
   └─ 检索未命中时：明确声明「知识库未覆盖」，不编造

检索增强（RAG）是小简可信度的地基：它回答内容问题时「看着原书页说话」。知识库收录三册文献（《长沙走马楼吴简的保护与整理》《吴简·卷》《资料汇编》）的扫描件，检索命中段落作为上下文注入提示词。系统提示词中写死了几条硬纪律：不得编造数字与出处；报告口径有出入时主动声明两说；学习者未提交作答前，不得给出答案或答案要点——只允许反问、提示、指方向。

5.2智能评阅链路（rubric 驱动）

学生点击「请小简评阅」
   │
   ▼
/api/guide（mode: grade）
   │  输入：题号 + 学生作答（文本协议 / base64 图）
   │        + 该题 rubric（评阅要点，服务端取出，前端不可见）
   ▼
模型按 rubric 逐要点比对学生作答
   │
   ▼
结构化输出（JSON）：
   { verdict: 成立 | 部分成立 | 不成立,
     analysis: { 对在哪 / 缺了什么 / 方向建议 } }
   │
   ▼
前端落判定章 + 解析流式渲染
   ▼
判定与解析写入本地 + 云端；答案修改后判定自动作废

三条设计原则：教师主权——rubrics 由教师逐题编制、存服务端，AI 只是判定引擎，教师改 rubric 即改评阅标准；三档判定而非打分——降低模型误判的表面冲击，「部分成立」反而是最有教学价值的一档（它明确告诉学生：你已经对了多少）；可反复——评阅不限次数、旧判定自动作废，把「评阅」从终审变成对话。

多模态画图题（2-q3a）复用同一链路：图片 base64 与题干一起送多模态模型，rubric 描述「合格的横断面示意图应包含什么」（编绳位置、简片排列曲率、向心方向），模型看图逐要点判定。作图类开放题的自动评阅由此第一次成为可能。

卷四 · 第六章仿真引擎：确定性过程模拟

6.1引擎与渲染分离

sim.ts 是六台工作台共享的纯计算引擎：定义每台工作台的「工步序列—参数空间—状态方程—结算函数」。它不 import 任何 React 模块；SimStageView 只是它的渲染器。这个分离带来三个直接收益：同操作永远同结果（评阅有据）；引擎可单测（十七组断言覆盖核心工步）；新工序接入只需写配置与状态方程，不碰渲染。

6.2确定性模拟的构造

每台工作台的建模套路一致：「报告数据 → 参数安全带 → 越带惩罚函数 → 事故触发器」。以脱色台为例：

// 温度对罗维朋蓝色值的影响（示意）
blueValue(temp) = temp in [45,50] ? targetBlue
                : targetBlue + deviation(temp) * penalty   // 越带变浅变慢

// 药剂错误的事故触发器
if (reagent === "borohydride") state.floating = true      // 简体上浮

// 结算函数：四指标加权（权重声明为教学设定）
settle(state) => { integrity, legibility, info, hours }

六台工作台的关键机制全部锚定报告事实：揭取的 2～3 厘米步距与「此步不可逆」、竹刀/金属刀的划伤差异、清洗力度安全带、饱水的逐月值守与微生物滞后显现（第 10 个月才发作的白斑，教「隐性风险」）、脱色的 45～50℃ 温度带与 20～40 分钟保温、脱水的填充率与宽度收缩率联动。工步动效（一次性播放、状态量平滑过渡）在渲染层用 CSS transition 实现，不参与状态计算。

6.3仿真与细问的分工纪律

明确一条边界：仿真管「手」，细问管「脑」。工作台训练操作判断（参数、时机、代价感知），细问训练原理推理（为什么、依据、机理）——两者内容不重复，仿真不泄露细问答案（比如细问要你论证「为什么 0.1% 压不住菌」，仿真只让你体验「0.1% 真的压不住」，机理层留给细问）。这条分工纪律在第二轮迭代中专门做过一次重构清理，删掉了两处重复与一处泄答。

卷四 · 第七章前端体验工程：字体、动效与演示模式

7.1字体子集化管线

纸墨主题对中文字体的要求是「宋体骨架 + 仿古笔意」，选型思源宋体（Noto Serif SC）。但全量字体 8MB+，对网页不可接受。管线：pyftsubset 按项目全文字符集（含备选字符表）生成 woff2 子集（Regular/SemiBold 两字重），构建脚本内置、可重复执行。两次踩坑记录：缺字——新增「赏」字后未重跑子集，渲染回退导致字形错位，修复为脚本内置全字符扫描；缓存——子集更新后浏览器仍用旧缓存，加 ?v=N 版本参数破除。教训沉淀：字体子集必须进构建管线，而非手工维护。

7.2动效系统

动效遵守「一次性播放 + 状态量平滑过渡」两分法：工步动作（如简入槽、药剂注入）是离散的一次性 keyframes（约 200 行 CSS）；连续状态量（泥污覆盖率、蓝色值、收缩率）用 CSS transition 平滑插值，让数值变化「有物理感」。全部动效尊重 prefers-reduced-motion。

7.3演示模式：一套小型编排引擎

DemoMode.tsx 实现了场景（scene）驱动的自动演示：

  • 场景脚本（scenes.ts）：18 个场景 = 标题 + 旁白文本 + 目标路由（或图片）+ 动作序列；动作类型：scroll / scrollTo / click / highlight（data-demo 属性或 rect 坐标定位）；
  • 编排引擎：场景切换 → 路由导航（useEffect 监听，绝不在 setState updater 内做导航——React 渲染安全的教训）→ TTS oncanplay 后执行动作序列（waitForElement 等待元素渲染）→ onended 进下一幕；TTS 失败降级为按文本长度估算时长；
  • 环境标志：window.__DEMO_MODE__ 全局标志让已登录的演示账号可停在登录页（阻止自动重定向）、让环节页全展开、让细问全部可进入——演示环境与学习环境互不污染；
  • 控制面板：底部统一控制栏（进度条 + 字幕 + 上/播/下/退出），body 加 320px 底部 padding 防遮挡。

G+补充：技术名词速查表（写给非技术读者）

二十五个高频技术词，一列看懂。按「你会在哪里遇到它」分组。

App Router

Next.js 的页面组织方式——「文件夹即路由」。环节页 /stage/1～/stage/6 共用一个动态路由 /stage/[id]。

SSG / 静态生成

页面在构建时预先生成为 HTML，访问时直接取成品——比现算快一个量级。工坊全部内容页走这条路线。

API 路由

服务端的接口函数。工坊只有三个（guide / tts / supabase-config），动态能力全部收口于此。

SSE / 流式

Server-Sent Events——服务器把回答一个字一个字「推」给浏览器。小简的回答「逐字流出」就是它。

zustand

轻量前端状态管理库。工坊用它保存你正在做的题、判定结果——配合 persist 中间件写进浏览器 localStorage。

localStorage

浏览器自带的本地存储。刷新页面不丢数据的第一重保障就靠它。

Supabase / PostgreSQL

托管数据库服务（底层是开源的 PostgreSQL）。云端进度同步的第二重保障；RLS 保证学生只能读写自己的数据。

RLS / 行级安全

数据库层的权限规则：每行数据带主人标记，规则规定「只有主人能读写这一行」——前端拿到钥匙也翻不了别人的墙。

RAG / 检索增强生成

Retrieval-Augmented Generation——先从知识库里检索相关原文段落，再让模型「看着材料」回答。小简不编书的底气所在。

多模态模型

能同时理解文字与图片的模型。画图题的「AI 看图评阅」靠它实现。

TTS

Text-To-Speech，文字转语音。演示模式的旁白配音（儒雅男声、语速 -10）。

rubric / 评阅要点

教师逐题编制的评分依据清单，存在服务端。AI 评阅的「宪法」——它只判定，不立法。

verdict / 判定

评阅结论的三档：成立 / 部分成立 / 不成立（外加存疑态「待判定」）。不打分数——降低误判冲击，保留修改空间。

系统提示词

写给 AI 的「岗位说明书」。小简的「先答后评」「不编数字」纪律都写在这里——行为约束的第一现场。

幻觉 / AI 幻觉

模型一本正经编造事实的倾向。工坊的治理组合拳：RAG 兜底 + 提示词纪律 + 三档判定 + 可反复评阅。

pyftsubset

字体子集化工具——只保留项目实际用到的字符，把 8MB 的中文字体裁到几百 KB。

woff2

网页字体压缩格式。配合 URL 上的 ?v=N 版本参数管理浏览器缓存。

Tailwind CSS

原子化样式方案。纸墨主题的色板、字号、间距以设计令牌集中在 CSS 变量层，一处定义全局生效。

TypeScript / TS

带类型检查的 JavaScript。十七道题的结构、题型、评阅要点的对应关系在编译期就被查一遍。

Express

Node.js 的老牌 Web 服务框架。工坊的自定义 server 用它包住 Next，同时服务页面与三个 API。

tsup

TypeScript 打包器。把 server.ts 打成单个 dist/server.js——部署产物简单到只有一个文件。

pnpm

高效包管理器。项目依赖安装、构建、启动全走它。

base64

把图片编码成文本的方式。画板题的作答图以 base64 存储、传输，与文本作答共用一条链路。

canvas

浏览器画布。画板题的画笔、成就卡的证书导出，都是它。

useEffect

React 的副作用钩子——页面渲染完后才执行的逻辑。工坊铁律：一切「跳转、计时、播音频」都进它，渲染期只做纯计算（踩过坑的教训）。
