# DESIGN.md · 走马楼吴简修复工坊

## 用户与场景

面向文物保护、考古、材料方向的本科生与入职培训人员。使用场景是「读一段工序说明，然后被追问」，
所以页面主体是**长文可读性**，不是仪表盘。

## 气质与意象

意象锚点：库房的长条工作台上摊开一枚饱水竹简，旁边是揭剥图、测色记录和一支尼龙勾线笔。
纸是米色的，字是墨的，编号章是朱砂的。

关键词：素、稳、可读、有考据气。不是"国潮"，不是水墨特效，是**档案与实验记录的质感**。

## 字体

- 标题、题号、印章：`font-serif`（Noto Serif SC / Songti SC）——这是"档案感"的主要来源。
  Noto Serif SC 为**自托管子集**（`public/fonts/*.woff2`，Regular + SemiBold 两字重，
  `font-display: swap`）：Android / Linux 没有预装中文宋体，不自托管整套衬线设计会静默降级为黑体。
  子集只含仓库内出现过的字符——往 `content.ts` / `exhibition.ts` 新增生僻字后跑
  `pnpm font:subset` 重新生成（脚本会报出源字体缺字形的字符，它们走回退链）。
- 正文：`font-sans`，正文行高 `leading-8`，长段落也能读。
- 数据：`font-mono` + `tabular-nums`，表格里的数字必须等宽对齐。
- 正文里的数字与编号（228 枚、J22、76 厘米、c①→c②）同样走数据口径：`font-mono` + `wj-water`，
  在长文中直接显影，不与表格两套标准。
- 第一节正文的分层：首段作导语（全墨色、首字下沉一格，serif 墨字，不缩进）；
  其余段落 `text-wj-ink/85` + 段首缩进两字符（中文书排惯例）。

## 布局

- 大厅顶部是一行页签：简牍发掘 / 简牍展示，压在同一条底线上，选中的那个用朱砂色下边框标出，
  左右方向键可切换。**不要写「上篇/下篇」这类序号前缀**，两块是并列关系，不是先后关系。
- 「简牍发掘」页签下直接是六张环节卡（`md:2` / `lg:3`），卡上有序号水印、一句话定位、
  一条关键数据、题量与题型。**卡片就是唯一的入口**——不要再在上面加一条「一 揭取 → 二 清洗」
  的流程条，同一批入口摆两遍只是重复，工序的先后关系靠卡片的序号和内容本身表达。
- 「简牍展示」页签是展厅首页（`ExhibitionHall.tsx`）：篇头（serif 篇题 + 副题 + 导语 +
  mono 信息条 + 赭色左缘的释文/图版声明）+ 五张板块入口卡（头图 + 序号章 + 简介 + mono 内容量），
  末尾一行汇编尾注。**板块内容不堆在页签里**，各自独立成页：
  /exhibition/discovery（四说并列卡）、/exhibition/forms（六展签，`<details>` 展读）、
  /exhibition/themes（八类卡 + 丘里双轨附注）、/exhibition/cases（案例入口 ×5）、
  /exhibition/reference（〔伍〕术语卡带「争论」章 → 〔陆〕出版表 → 〔柒〕学术意义 → 〔捌〕资料来源）。
- 展示篇独立页共用 `ExhibitionShell`：固定顶栏（返回展厅 → `/?tab=exhibition` + 「简牍展示 ·
  板块名」）+ 内容容器（网格页 max-w-6xl / 长文页 max-w-4xl）；页头是序号章 + serif 大标题 +
  一句话（`BoardHeader`）。
- 案例精读是五个独立页（`/exhibition/case/N`）：同一外壳 + 篇头（案例序号 + serif 标题 +
  一句话）+ 字段驱动正文（背景 → 释文块 → 对照表 → 图版 → 程序链 chips → 解读 → 补记）+
  底部案例间导航。纯阅读，无作答。
- 展示篇的照片是**真实文物照**（CC0 / 博物馆官网配图），署名永远跟在图题下（`FigureCard` 的
  credit 行）；释文块是竹青左缘细边 + 纸色底 + serif（`SlipText`）。与发掘篇的 AI 示意图
  标注体系（「示意 ·」开头）互不相同，别混。
- 环节页：单栏，环节资料即全部内容；顶栏固定、资料区为唯一滚动区。
- 环节页的环境底景：**每个环节用自己的意象图**（`/stage-N.jpeg`，与大厅卡片封面同图）做固定底景——
  图透明度约 0.22，上罩 `wj-bg` 纵向渐变纱（顶 84% / 中 55% / 底 90%，上、下浓中间淡），
  纸色卡片压在其上阅读。底景固定不动、资料区滚动，像在工作台上拖动纸页；换环节即换环境。
- 环节资料按**三节**推进：首节是工序说明正文，**不加节小标**，导语首字下沉直接开篇；
  其后「关键数据」（数据卡 + 报告原始数据表归同一节）与「细问」两节保留节首小标
  （serif 墨色标题，题下压一条 `wj-line` 细线），不编序号。
- 「关键数据」节节首配一张本工序的**示意图版**（`/fig-stage-N.jpeg`）：照片卡样式（边框 + 纸底），
  图下压一行图题——朱砂「图 一/二…」+ 墨色说明，说明一律以「示意 ·」开头。
  图是 AI 生成的示意图，**不冒充真实文物照片**；简上字迹虚化，不给简牍编造内容。
- **三节一节一屏，同屏只出现当前这一节。** 首屏是第一节；底部虚线宽按钮（「接着读」+ 下一节标题 +
  下箭头）切换到下一节并平滑滚动到位，上一节同时离场；第二节起底部另有「上一节」按钮回读；
  当前节序号按环节存本机，刷新回到已读位置；读到最后一节后底部才出现「上一环节 / 下一环节」导航。
- 环节页顶栏保留六道工序的横向导航，但**未解锁的环节在导航里同样置灰带锁**，不能点。
- 「小简」立绘固定右下（`h-32` / `sm:h-44`，透明底，`z-40`；`public/guide-avatar.png`
  已降采样到 640 高，原图存 `assets/originals/`，显示尺寸不超过源图的 1/2，高分屏不糊），
  气泡在立绘上方右对齐、可收起；居中排布的「接着读」宽按钮不被遮挡。

## 交互原则

- **六个环节顺序解锁。** 环节 1 常开；环节 N 在环节 N−1 被读完后解锁。
  大厅未解锁卡片：封面加灰度压暗、右上角「未解锁」锁标、底部「答完『上一环节名』后解锁」，
  不可点击；直接输 URL 进入未解锁环节时，环节页整体换成解锁提示（指回上一环节），不展示内容。
- **完成是自动的，没有手动标记入口。** 最后一道细问的答题框写入内容（非空白）即自动完成，
  顶栏戴上一枚竹青「已完成」印记（纯展示、不可点击），下一环节的解锁也随之自动发生。
  细问节末尾留一行小字说明这条规则（未完成时提示「作答即完成」，完成后换成竹青确认）。
- **细问一题一答、题内一小问一答（QuestionWizard）。** 同屏只出现当前一道题：
  题号圆点标进度（✓ 已答 / 朱砂当前 / 可进入 / 置灰待解锁），全部小问答完「下一题」才解锁
  （与环节间顺序解锁同一精神），进度圆点可回看已答的题，进入环节时自动定位到第一道未答完的题。
  题内的小问（(a)(b)(c)…）**逐个展开、各自带作答框**：写完当前小问才露出下一问，
  答案按小问分键存储（`answerKey(stageId, qid, partLabel)`）；无小问的题整题一框。
  作答均为纯草稿、无提交对象，实时存进 localStorage，刷新不丢。
  题卡右上角「问小简这道题」直连 AI 助教（window CustomEvent 桥，`guide-bridge.ts`）：
  面板未开时以该题上下文作开场触发语，已开时作为 hidden 通知追加进对话。
- **数字人向导「小简」常驻右下角。** 官方提供的透明底 Q 版简牍少女立绘
  （`public/guide-avatar.png`，源文件 `assets/AI助教.png`）**无底悬浮**：不裁徽章、不加边框，
  用 `drop-shadow` 落地投影 + 呼吸浮动。表情四态字段保留（微笑 / 讲解 / 思索 / 欢喜），
  当前统一用官方形象，待官方表情差分图到位后按态切换。
  她**实时感知学生位置**——路由、各环节读到的节序号、完成记录，任一变化即换表情与台词；
  气泡右上角用 `wj-dim` 小字显式标注她看到的当前位置，让感知可被察觉。
  **只在环节页出场**：大厅、登录 / 注册页都没有向导与助教——她的位置感只作用于
  「哪个环节、读到哪节、是否完成」。
  台词全部是**预设脚本**（`guide-lines.ts`）、打字机逐字出场；气泡上「换一句」轮换备选句，
  点 × 收起气泡（位置变化时自动再展开）。台词里的事实与数字与 `content.ts` 同口径，只能出自报告。
- **点击立绘，数字人就地「变换」成助教对话面板，不另起一页。** 点击后立绘脱离文档流
  （绝对定位回同一锚点）并向右下缩小淡出（`scale 0.3` + 位移，收起时弹回占位），
  对话面板**固定占据视口右侧全高**（`GuideChat`，`fixed inset-y-0 right-0`，
  移动端全屏、sm 起 `w-96`，从右滑入，Esc 可关）。**桌面端（lg+）面板展开时正文让位**：
  GuideAvatar 给 `<html>` 打 `data-wj-chat-open` 标，环节页滚动容器（`.wj-chat-dodge`）
  右侧让出 `24rem`（与面板同宽，带过渡），阅读与对话并排互不遮挡；
  小屏面板全屏覆盖，点 × 或 Esc 收起。右下角列容器保持指针穿透
  （`pointer-events-none`，只有气泡与立绘本体 `auto`），气泡周围的空白不吞正文的点击。
  面板里双方带头像交互：头部名签前是小简的
  圆形头像（全身立绘放大取头部，与右下角同一张脸）；消息区助教气泡在左
  （`wj-raised` 底 + 小简圆头像）、学习者气泡在右（竹青淡底 + 学习者字母章——
  登录邮箱首字符，`bg-wj-bamboo/15` 圆形），头部 = 头像 + serif 名签 +
  当前话题小字（环节名 · 当前节名，随翻节实时变化）+ × 收起；上下文实时跟随
  学生位置：换环节以 `key=环节id` 重挂重新开场；环节内读到的节（工序说明 /
  关键数据 / 细问）随请求透传给后端写进系统提示，助教的开场与提问围绕当前节
  展开——还在读工序说明时不抛细问，翻到细问节才请作答；翻节时自动发一条
  不渲染的翻节通知让小简接住新话题。真实 LLM 对话（`/api/chat` SSE 流式 +
  环节材料注入 + 三册参考书 RAG），教学纪律是「先答后评、不直接给细问答案」。
  底部输入框 Enter 发送、
  Shift+Enter 换行（中文输入法组词中的 Enter 不触发）。对话只存组件 state、收起即卸载、
  重开重新开场。对话框展开时预设台词气泡让位（收起了对话框气泡再回来）。

## 禁忌

- 不要水墨笔刷、不要毛边纸贴图、不要竖排正文（竖排好看但长文不可读）。
- 不要 emoji，用 Lucide 线性图标，尺寸不超过 `h-6 w-6`。
- 圆角只用 `rounded`(4) / `rounded-md`(6) / `rounded-lg`(8)。
- 不要用 `wj-dim` 写正文——对比度不够。
- 表格宽了要在自己的容器里横向滚动，页面本身永远不横向滚动。
