# 走马楼三国吴简修复工坊·智能体应用场景建设报告

---

## 一、应用场景的建设过程与建设进度

### 1.1 建设背景

1996年，长沙走马楼J22古井出土十余万枚三国吴简，是中国二十世纪以来最重要的简牍发现之一。然而，考古修复是一个高度专业化的领域，学生难以通过传统课堂讲授真正理解"为什么这样修"的决策逻辑。本应用场景以《长沙走马楼三国吴简的保护与整理》为内容基底，将真实的考古修复流程转化为可交互的教学工坊，让学生在模拟实操中理解每道工序背后的科学判断。

### 1.2 建设过程

建设分为四个阶段：

**第一阶段：内容设计与知识结构化（已完成）**

- 以考古报告原始数据为唯一来源，按实际修复工序拆分为六个环节：揭取→清洗→绑夹与核对→饱水保存→脱色→脱水。
- 每个环节设三节内容（工序说明、关键数据、细问），细问从报告中的真实数据出发——如揭取环节给出叠压关系原始记录，要求学生排出层序；清洗环节给出6道工序的工时统计，要求计算人力与工期。
- 同步构建简牍鉴赏展厅，五个板块（发现与归属、形制分类、主题释读、案例精读、关键术语），内容出自资料汇编《长沙走马楼吴简：种类、主题与释读》。
- 建立知识库数据集 `wujian_knowledge`（三册扫描书），用于AI助教的检索增强生成（RAG）。

**第二阶段：技术架构搭建（已完成）**

- 选用 Next.js 16 App Router + React 19 + TypeScript 技术栈，自定义 Express 服务端。
- 接入 Supabase 实现用户认证（邮箱密码登录/注册）与行级安全策略。
- 使用 coze-coding-dev-sdk 接入豆包大语言模型（doubao-seed-2-0-lite），支持文本与图像多模态输入。
- 采用 zustand + localStorage 实现前端状态持久化，配合数据库双通道同步——学生退出再进入不丢作答记录。
- 设计纸墨主题视觉系统（朱砂、赭石、竹青、墨色），衬线字体子集化优化加载性能。

**第三阶段：AI助教与交互系统开发（已完成）**

- 开发数字人向导"小简"：右下角常驻气泡，根据学生实时位置（当前环节、读到的节序号、完成记录）切换表情与台词；点击展开AI对话框，支持流式对话（SSE）与知识库检索。
- 开发"请小简评阅"功能：学生提交答案后，AI按评阅要点给出三档判定（成立/部分成立/不成立），并流式输出解析——点依据、点缺口、给一个能自己走下去的方向，不端完整标准答案。
- 实现五种作答题型：分层排序（拖拽入层）、单选判断（附理由说明）、多选（附理由）、左右匹配、画板作答（canvas画笔，多模态判分）。
- 开发成就卡系统：学生完成全部六环节后填写学号姓名，解锁简册编联意象的结业证书，支持下载为PNG图片。

**第四阶段：演示模式与优化迭代（进行中）**

- 开发内置演示模式：18个场景自动播放，配合TTS语音旁白同步操作界面——展示登录页、切换页签、进入各环节、点击小简、展示五种题型、展示进度与成就卡。
- 持续优化：移除加载页面提升体验、修复LaTeX公式渲染、精简字体子集、统一展厅交互模式等。

## 二、应用场景在优化教学方面的具体实践

### 2.1 从报告原始数据出发设计题目

传统考古教学以教师讲授为主，学生被动接受结论。本场景的核心设计原则是**"有数据处从数据反推结论"**——题目不直接给结论，而是给出考古报告中的原始数据，要求学生自行推算。例如：

- **揭取环节**：给出叠压关系原始记录，学生需排出简牍层序。合法排列不唯一——任何满足给定先后约束的序列都算正确，培养学生理解"考古证据允许多解"的科学思维。
- **清洗环节**：给出6道工序的工时统计表，学生需计算"人力减半后工期变为几年"，从真实数据理解工程决策。

### 2.2 五种题型对应五种认知维度

| 题型 | 认知维度 | 教学目标 |
|------|---------|---------|
| 分层排序 | 空间逻辑 | 理解简牍叠压关系与层位推断 |
| 单选判断 | 批判性思维 | 逐条辨析陈述正误并补充依据 |
| 多选 | 综合判断 | 从多项中筛选正确答案并说明理由 |
| 匹配 | 关联思维 | 建立药剂与效果、工序与产物之间的对应 |
| 画图作答 | 空间表达 | 用画笔画出简册横断面示意图，多模态AI判分 |

### 2.3 AI实时评阅替代教师一对一辅导

每个答题框下方设有"请小简评阅"按钮，学生提交后AI在数秒内给出三档判定与流式解析：

- **成立**：答案符合评阅要点，指出依据正确之处。
- **部分成立**：方向对但有缺口，点出缺什么、怎么补。
- **不成立**：指出核心错误，给一个能自己走下去的方向，不直接给标准答案。

这套机制让每个学生都能获得个性化的即时反馈，解决了大班教学中教师无法逐一评阅学生作答的痛点。评阅要点（rubrics）按小问级存储，精度到每个子问题。

### 2.4 进度可续机制支持分次完成

六环节共约60道细问，学生不可能一次完成。系统采用三重保障：

1. **本地持久化**：草稿、评阅判定、画板图、提交定稿全部自动保存到浏览器。
2. **云端同步**：登录后作答进度自动同步到数据库，2秒防抖推送，退出时强制同步一次。
3. **重做机制**：每个环节卡片可一键重做，清除该环节所有记录重新开始。

首页环节卡片实时显示进度（已提交X/Y、评阅X/Y、进度条），学生随时了解自己的完成情况。

### 2.5 演示模式支持课堂展示

内置18场景演示模式，配合TTS语音旁白自动操作界面——展示登录流程、两个世界（发掘与鉴赏）、六道工序、AI助教对话、五种题型、进度与成就卡。教师可在课堂上直接播放，也可作为新生入门引导。

### 2.6 成就卡激发学习动机

学生完成全部六环节后，填写学号姓名即可解锁成就卡——以简册编联为意象的结业证书，含朱砂印章、六枚竹简代表六道工序、评阅统计四格、签发日期，可下载为PNG图片。这既是学习成果的可视化认证，也满足了学生的成就感与分享欲。

## 三、与应用场景建设相关的其他成果

1. **知识库数据集**：建立 `wujian_knowledge` 数据集，收录三册与走马楼吴简相关的扫描文献，支持AI助教在对话中检索原文页面并以图片形式呈现给多模态模型，实现检索增强生成（RAG）。

2. **讲稿与演示视频脚本**：编写了从讲故事角度介绍智能体的讲稿（六幕结构），以及配套的演示视频脚本（8个场景，含画面动作与旁白文本），可用于教学推广与成果展示。

3. **纸墨主题视觉系统**：设计了一套与简牍文物气质匹配的UI系统——朱砂红（强调）、赭石（警示）、竹青（成立）、墨色（正文）的配色方案，Noto Serif SC衬线字体子集化，纸墨纹理背景，统一展厅交互模式。

4. **评阅要点体系**：为约60道细问编写了评阅要点（rubrics），按小问级存储，是AI评阅的判分依据。这套要点本身也是一份结构化的教学评价标准文档。

5. **内容方案文档**：与 `副本走马楼吴简修复工坊_内容方案.docx` 逐段对应，确保线上内容与原始教学设计一致。

## 五、下一步工作计划

### 5.1 近期（1-3个月）

1. **移动端适配优化**：当前界面针对桌面端设计，画板题和匹配题在小屏幕上操作不便，需针对性优化触屏交互。
2. **教师管理后台**：开发教师端，支持查看全班学生进度、评阅统计、常见错误分布，辅助教师了解学情。
3. **题目扩充**：在现有六环节基础上，增加更多从报告数据出发的细问，特别是饱水保存和脱色环节的实验设计类题目。

### 5.2 中期（3-6个月）

4. **学情数据分析**：利用已积累的答题数据，分析各环节的错误率分布、常见错误类型，为教学改进提供数据支撑。
5. **知识库扩充**：将更多走马楼相关文献纳入知识库，提升AI助教检索的覆盖面与准确率。
6. **多场景复制**：以本场景为模板，开发其他考古遗址的修复工坊（如里耶秦简、银雀山汉简），形成系列化的考古教学智能体。

### 5.3 远期（6个月以上）

7. **协作学习模式**：支持学生分组完成修复任务，组内分工（如一人负责揭取、一人负责清洗），培养团队协作。
8. **虚拟现实扩展**：探索将画板题升级为3D简牍操作界面，让学生在虚拟空间中"亲手"翻转、清洗简牍。
9. **开放平台化**：将评阅框架（题型+评阅要点+AI判定）抽象为通用教学组件库，供其他学科复用。
