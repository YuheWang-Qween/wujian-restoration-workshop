# 走马楼三国吴简 · 简牍修复工坊

一个教学智能体，分两篇：

- **简牍发掘**——已完成。按实际修复工序组织，**六道工序即六个环节，每个环节一个入口。**
- **简牍展示**——占位。环节划分与内容方案待补，页签在，内容暂未开放。

两块在大厅顶部同一行，用页签自由切换。下面讲的是「简牍发掘」。

| # | 环节 | 一句话定位 | 细问 |
|---|---|---|---|
| 一 | 揭取 | 唯一一道不可重来的工序 | 排序题 / 判断题 / 机理分析题 |
| 二 | 清洗 | 让字迹第一次真正可见 | 选择题 + 说明理由 / 工程试错分析题 / 工时反推题 |
| 三 | 绑夹与核对 | 身份不能在工序之间掉线（轻量环节） | 编号系统分析题 / 后果分析 + 方案设计题 |
| 四 | 饱水保存 | 持续时间最长、失控风险最隐性 | 假设排除题 / 多维决策题 / 排序题 + 机理分析 |
| 五 | 脱色 | 从「能保存」进入「能使用」 | 数据判读题 / 反常数据解释题 / 决策题 |
| 六 | 脱水 | 不可逆程度最高的一道 | 各向异性题 / 数据计算 + 材料分析题 / 流程决策题 |

共 17 道细问。每个环节页分两部分：**为什么必须有这个环节**（含报告原始数据与数据表），
以及**细问**；右侧是导师，逐问评阅。

每道细问底下有自己的答题框：写的内容实时存在本机（刷新不丢），点「提交给导师评阅」
就把这份答案连同题号推进右侧对话，导师据此评阅。旁边的「向导师提问」只是把题号填进输入框，
用来问问题而不是交答案。

## 智能体是怎么带教的

导师的行为写在 `src/lib/workshop/prompt.ts` 的总纲里，几条硬约束：

- **先答后评**：学习者没给答案之前不给答案、不给要点。
- **一次只推进一小问**，不把 (a)(b)(c) 一次性抛出。
- **计算题必须要过程**，只给数字的退回重做；口径（取中值、按几个工作日）要写明。
- **排序题必须问"哪些不可判定"**，排出唯一序列而不指出不可判定的单位对，是本类题的核心失分点。
- 评阅给「成立 / 部分成立 / 不成立」+ 依据 + 缺口，不打分数。
- 只用注入的报告数据，不编造数字与出处；报告本身口径有出入的地方主动说明。

每道细问的评阅要点放在 `src/lib/workshop/rubrics.ts`，**只走服务端**，不进浏览器包。

## 本地运行

```bash
pnpm install
pnpm dev
```

访问 http://localhost:5100 。

本地环境没有模型凭据时，导师会提示「导师未接通」并说明原因，环节资料与细问照常可读；
部署到 Coze 运行时后凭据自动注入。

## 数据来源

全部内容出自《长沙走马楼三国吴简的保护与整理》。报告不同章节之间存在口径差异的六处
（有字吴简总数、出土总数、大木简数量、坨数、纤维素结晶度、防腐药剂名），
已在大厅页「报告内部数字出入备案」里逐条列明本工坊采用哪一个口径。
